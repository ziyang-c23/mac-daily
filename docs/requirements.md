# 目标与当前范围

概览需求：可编辑的双列状态卡片、固定应用与快捷功能纵向排列，菜单栏收纳保留独立页签；默认CPU、GPU、内存、磁盘、网络、电池，温度按需加入。卡片进入详情，固定应用可增删和拖动排序，系统功能区分直接开关和设置跳转。电源管理采用定时唤醒断言及系统设置入口。[使用说明](dashboard.md)记录具体功能。

MacDaily 统一个人的基本日常软件需求，减少辅助软件之间的切换。个人顺手、简洁和低后台开销优先。开源应可构建、说明清楚、许可证明确，不增加平台化功能。

## 鼠标要求

平滑及双轴反向、修饰键临时关闭平滑、外接鼠标独立指针控制、中键和侧键映射、按钮加滚轮、四方向手势、按应用例外和暂停恢复。默认不接管指针，预设不自动启用。触控板与未知输入不当作普通鼠标处理。

窗口动作是鼠标绑定的一种输出类型，不能同时发送旧快捷键。规则作用于触发时的前台应用；切换应用后取消。触控板通过独立模块接入，具体手势与原生设置分工见[触控板说明](trackpad.md)。

## 窗口要求

1. 参考 Magnet：边缘半屏、角落四分屏、顶部最大化、底部三分屏并可沿底边扩展。
2. 窗口实际发生平移、尺寸保持稳定后才识别拖拽；文本选择、文件拖动、调整窗口尺寸和非标准窗口不吸附。
3. 预览不抢焦点、不拦截鼠标；松手提交前重算区域并核对目标。Escape、应用切换、屏幕变化、失权和休眠取消未提交操作。
4. 布局使用屏幕可用区域，考虑菜单栏、Dock、屏幕偏移和不同方向。读取实际结果，对应用最小尺寸限制如实提示。
5. 连续吸附保留原位置；用户自由移动或调整尺寸后建立新的还原基线。
6. 设置页和菜单栏动作记住上一个外部窗口，避免调整设置窗口。提供专用练习窗口，不把它与真实工作窗口混淆。
7. 拖拽例外只影响自动吸附；手动按钮、鼠标绑定仍可主动调整窗口。
8. 旧配置只读迁移，保留原规则；首次保存升级格式前备份 schema 1 或2，保持既有窗口模式。
9. 自定义激活区域与目标布局独立，横屏和竖屏分别配置；支持移动、缩放、启停、优先级和自定义目标矩形。重叠时首个启用区域优先，无匹配则不吸附。
10. 编辑采用草稿、保存和取消，不直接改写实时设置；默认边缘模式继续可用。提示层不截获输入、不抢焦点，仅实际窗口拖动时显示。

## 长期范围

应用管理按下述 v0.12 方案实施。键盘快捷操作、照片整理与系统维护按个人需要扩展。

## v0.12 应用管理

目标是集中查看已安装应用、预览卸载关联文件、整理残留及管理普通启动项。页面设“应用”“残留”“启动项”三个页签，使用现有中英语言设置。操作说明见[应用管理](applications.md)。

### 参考与本机观察

| 参考 | 采用内容 |
|---|---|
| 本机 App Cleaner & Uninstaller 10.0.1 | 应用列表与关联文件双栏、残留分组、按来源区分启动项；[官方说明](https://nektony.com/help/app-cleaner/getting-started) |
| macOS | 区分登录时打开、后台 App 活动和扩展；[原生设置说明](https://support.apple.com/zh-hans/guide/mac-help/mtusr003/27/mac/27) |
| Freemacsoft AppCleaner | 拖入应用后查看关联项的简短流程；[产品入口](https://freemacsoft.net/appcleaner/) |
| feherk/AppCleaner | SwiftUI 应用清单、关联文件分组与残留搜索；MIT；[源码](https://github.com/feherk/appcleaner) |
| Ignition | launchd 项目来源、启用和运行状态的表达；MIT；[源码](https://github.com/Acelogic/Ignition) |
| Pearcleaner | 应用详情与关联项交互；其许可含 Commons Clause，仅参考产品行为；[许可](https://github.com/alienator88/Pearcleaner/blob/main/LICENSE.md) |

本机 App Cleaner 将 BetterAndBetter 的偏好、HTTPStorages 和 Group Container 列为关联项，说明“关联”并不等于缓存。它还将 `~/.conda` 列为 Anaconda 残留；该目录可能由其他 Conda 安装共用，MacDaily 不据此认定其独占归属。启动项页部分条目只提供“打开偏好设置”，与本机原生设置的管理方式一致。

### 应用清单

默认读取 `/Applications`、`~/Applications` 及其中普通应用分类目录；支持添加目录或拖入应用。包内辅助应用归到所属应用，不重复列为主应用。相同 Bundle ID 的不同安装副本按路径区分。

列表显示图标、名称、版本、大小及运行状态，支持搜索、按名称或大小排序。详情显示路径、Bundle ID、开发者、二进制架构、应用本体大小和关联文件大小，并提供 Finder 定位及复制路径。大小后台计算，选择应用时才查找其关联文件；不在启动 MacDaily 时遍历资料库。系统自带应用作为只读项目。

### 卸载与关联文件

选择应用后按“应用本体、缓存与日志、偏好设置、应用数据、共享项目”分组，展示路径、大小及归属依据。

- 默认勾选应用本体、可确认独占的缓存和日志；支持多选应用统一预览。
- 偏好、Application Support、HTTPStorages、WebKit 数据、Containers 和 Group Containers 默认不选。
- Bundle ID 使用完整名称及明确边界匹配；应用名称相似只形成候选，不成为默认删除依据。
- Group Container 通过应用声明的 App Group 标识关联，并列出已发现的共同使用者；Team ID 或厂商前缀相同不代表独占。
- 同一 Bundle ID 还有其他安装副本时，共用数据和缓存默认不选。

勾选列表本身即卸载预览，底部显示所选项目及合计大小，点击“移入废纸篓”执行，逐项展示结果。运行中的目标先正常退出；未退出时保留待处理项目。专用卸载器或包管理器管理的应用显示对应管理入口：识别到 Homebrew Cask 时打开对应 Cask 管理说明并提供命令复制，不将直接丢弃本体冒充完整包管理卸载。涉及系统服务或扩展的应用优先使用已找到的厂商卸载入口，明确显示其管理来源。

### 残留

点击扫描后，检查限定用户资料库目录中的 Bundle ID 命名项目，结合应用清单和 LaunchServices 中仍存在的应用路径判定是否找到对应安装。废纸篓中的副本不算已安装。结果以“未找到对应应用”分组，显示匹配依据，默认不勾选。

共享容器、厂商公共目录和仅名称相似的目录单列。开发环境、项目、模型与数据集不因缺少同名 `.app` 被认定为残留。支持忽略项目，复用同一个预览与废纸篓处理流程。

### 启动项

| 类型 | 展示与操作 |
|---|---|
| MacDaily 自身登录启动 | 复用现有 SMAppService 设置 |
| 当前用户 `~/Library/LaunchAgents` | 显示标签、来源、执行文件、启用及运行状态；提供启停 |
| 其他应用登录项与现代后台授权 | 打开“系统设置 → 通用 → 登录项与扩展”管理 |
| `/Library` 启动代理及守护进程 | 展示可读取信息、定位文件及原生管理入口 |

启用状态、已加载状态及进程运行状态分别表达；不能只凭 plist 中的 `Disabled` 字段判断。用户代理启停通过当前用户的 launchd 域处理，保留原 plist。现代后台项目中无法读取的明细由原生设置展示，不以目录扫描伪造完整清单。

[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) 管理本应用包内的辅助程序，不是控制所有第三方启动项的通用接口。扩展、后台活动及系统服务保持各自管理来源，不统一伪装成普通应用开关。

### 实现结构与验证

新增 `ApplicationInventory`、`ApplicationAssociationResolver`、`ApplicationCleanupService` 和 `StartupItemsService`；SwiftUI 页面只发起查询和操作。应用卸载使用独立的包处理策略，复用系统废纸篓调用及逐项结果，不放宽空间模块对应用包的限制。关联规则有明确路径与依据，不引入全盘哈希或递归完整性清单。

清单、关联结果及大小保留在内存；只持久保存扫描目录和忽略项。新增设置时升级 schema 8，沿用已有配置迁移与备份，保留既有模块配置。扫描可取消，批量更新界面；空闲时没有周期扫描。

依次实现清单与详情、关联预览与废纸篓、残留、启动项及中英界面。集中验证具有实际歧义的场景：同 Bundle ID 多副本、包内辅助应用、共享 App Group、名称相近应用、已移除应用残留、运行中应用拒绝退出、移入废纸篓部分失败，以及 launchd 启用与运行状态差异。卸载使用项目内样本和注入的废纸篓接口；启动项启停使用本模块拥有的临时用户代理。个人应用与启动项只做读取，真实移除由用户选择目标。

应用页面位于“日常工具”，交付源码、应用包及[中英使用说明](applications.md)。


## v0.4 手势易用性

保留个人已验证的两个侧键映射。未验证的方向手势与滚轮组合不自动启用；分组显示状态，提供明确的预设入口。识别反馈不记录原始输入或键盘文本。

提供只识别、不执行动作的独立试用面板，与正式运行共用方向识别和鼠标状态机。试用与录制共用暂停状态，最后一个活动结束后才恢复；退出应用不重新启动监听。试用结果与正式应用中的硬件事件归属、快捷键执行分开验证。

## v0.6 空间检查与整理

整盘概览为默认入口；采用矩形面积图，目录列表和地图联动。无权限、被排除、失败和未完成的范围明确记录。文件大小与占用估算区分，不能把移入废纸篓的字节视为已释放。

重复比较需独立启动，先按大小再分段、完整哈希和字节核验；保留一个有效副本。缓存采用内置规则，开发缓存独立说明代价；uv/pnpm、模型、数据集、虚拟环境和任意项目产物不自动处理。所有清理先预览，默认不选中，仅调用系统废纸篓，不永久删除、提权或自动结束进程。

[空间模块说明](storage.md)记录首版规则与参考，验证记录单独报告测试结果和未覆盖条件。

## v0.7 地图阅读

概览地图默认占据约62%的地图/列表可分配高度；可拖动可见的调整条，保留列表最小操作空间。增加960×640pt大幅地图视图，复用当前目录与选择，支持面包屑导航，关闭不重新扫描。

## 菜单栏管理

控制面板内直接设置常显/收纳分组和排序，支持拖动与逐项按钮，结果同步至系统菜单栏。左键打开应用图标/名称聚合面板，右键保留原工具菜单。原菜单打开期间保持展开，关闭后按设定时间收起。使用本机macOS27的分隔项机制。

## v0.13 鼠标手势

右键、中键和侧键独立配置，八方向按等分扇区识别，默认36 pt，松手执行一次。支持原生点击恢复、按钮加滚轮、BetterAndBetter选定规则迁移，以及快捷键、窗口和系统动作的共用执行。

识别练习保留局部模拟；真实鼠标检查使用正式设备适配、配置与状态机，只识别不执行。运行状态、规则启用数量、识别与执行反馈分别展示。schema9为MouseBinding增加共用动作和四个斜向，旧规则保持实际动作并备份旧配置。详见[鼠标说明](mouse.md)。
